# Standard battery reads and encrypted-storage prerequisites

11 November 2026. Native source candidate over the actual full20; not a full
image, installed change or electrical/encrypted-I/O acceptance.

Existing patch0123 separates standard observed start/end thresholds from the
writer lease. Fixed typed settings GETs retain transport/source/epoch, active
control and partial-read checks. A failed read stays an error; observed values
do not grant writer admission or renew a verified-control cache. The disabled
band remains standard0/100. Existing admitted clients retain their verified
cache. No daemon, loop, current/CV writer or automatic reapplication is added.

Its numeric request validation also follows the exact Uke OEM start50..95 and
end55..100 bounds, preserving the standard0/100 disable representation. This
rejects unsupported generic UI targets before any guard or firmware operation;
it is not authority to send a supported target without the existing admission.
Actual four-mode on/off getter/settings tests include those boundaries, busy
transport, source changes, partial errors and unchanged admitted clients.
Missing-getter and old-bound mutations must fail their actual runtime checks.

The unchanged eight-option storage fragment requests dm-crypt, dm-inlinecrypt,
fscrypt/EXT4/F2FS integration and software crypto fallback. Prior source56's
receipt is historical evidence; rebuild the six real ARM64 objects against
current full20. Compile the battery object again with the same final config.
Retain all758 parent source fields during this native receipt. Full-image
integration must separately declare each intended config difference and keep
all other config/DT/audio/firmware/recovery features.

No encrypted volume, key, mount, mapper admission or boot path is activated.
Original Fedora cryptsetup/systemd remain the intended userspace. Ordinary
LUKS is not proof of ICE use, and Linux7.3 dm-inlinecrypt has no automatic
cryptsetup integration. TEE/HWKM/wrapped-key lifecycle and actual FDE/FBE I/O,
unlock, power-loss and Live Recovery acceptance stay open. No new runtime RPM
or firmware/calibration payload is introduced.
